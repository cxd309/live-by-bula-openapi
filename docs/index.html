Live! by BULA OpenAPI

An unofficial OpenAPI 3.1 specification for the Live! JSON API, the feeds behind Live! by BULA, the public results interface used by recent BULA, EUC and WFDF ultimate events.

Unofficial. Derived from the published Live! source and verified against live deployments. Live! by BULA is © BULA Ltd. UltiOrganizer is a separate project. Neither has published, endorsed or reviewed this specification, and the API may break without warning.

One specification per distinct response shape. Check app_version in a deployment's _heartbeat.json to see which applies.

The short version

Every event exposes the same set of static JSON files. Nothing is hardcoded - start at the heartbeat to discover the season id and base path, then build the rest of the URLs from it: 

GET /{prefix}/live/data/_heartbeat.json
    -> config.LIVE_SEASON_ID        e.g. "wbuc2025" (casing varies, use verbatim)
    -> config.STATIC_CACHE_BASE_URL e.g. "/live/data/"
    -> app_version                  e.g. "1.9.14" or "1.9.17"

GET {base}/{seasonId}_reference.json             season, divisions, pools, teams, countries
GET {base}/{seasonId}_teams.json                 per-team W/L, points for/against, spirit
GET {base}/{seasonId}_teams_{teamId}.json        squad list + player stats + spirit given/received
GET {base}/{seasonId}_games.json                 every game (scores, no detail)
GET {base}/{seasonId}_games_active.json          games in or near the current round
GET {base}/{seasonId}_games_{gameId}.json        rosters, every goal, spirit breakdown
GET {base}/{seasonId}_standings_{poolId}.json    one pool's table and fixtures
GET {base}/{seasonId}_spirit_{seriesId}.json     division spirit leaderboard
GET {base}/{seasonId}_players.json               index of every player id
GET {base}/{seasonId}_statistics_{seriesId}.json division player leaderboard
GET {base}/{seasonId}_statistics_top.json        event-wide single-game records
GET {base}/{seasonId}_config.json                full deployment config + provenance

These static files send Access-Control-Allow-Origin: *, so they can be read straight from a browser on any origin.

There is also a dynamic index.php?view=live/api endpoint which returns identical bodies but sends no CORS headers, so it is not usable cross-origin and therefore not specified here.
